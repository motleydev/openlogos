# Blueprint validation

`python3 tools/validate.py` uses Python 3 and `jsonschema` (Draft 2020-12). It has no network or provisioning side effects. The infrastructure agent will pin these dependencies in the target repository's Nix shell.

Validation checks schema shape, role references, dependency cycles, safe paths, budgets, source IDs and synthetic hashes. Negative cases verify rejection of an unknown agent field, task cycle, absent dependency, traversal path unsigned production manifest, exported credential fields, mismatched ink coordinates, fabricated citations and out-of-scope research evidence.

It does not validate the complete intended application protocol. Production schemas must grow alongside implementations, and a runtime importer must enforce all semantic and authority boundaries in `specs/00-import-contract.md`.

Revision 2 validates 12 schema/data pairs and 9 negative cases, including workspace, ink and research context boundaries.

B062 adds the archived 1.0 workspace example as a thirteenth pair and `check_workspace`: every layout profile places every pane exactly once, within its class's column limit (a collapsed link group counts as one column), with widths only for visible panes and collapsed groups that exist. Seven negative cases cover a profile that drops a pane, one that places a pane twice, one that carries another class's layout, an unknown device class, a compact profile with two columns, a 1.0 file with profiles and a 1.1 file without them.

B070 adds the workspace 2.0 line: `examples/workspace.json` validates against `schemas/workspace-2.schema.json` and `examples/session.json` against `schemas/session.schema.json`, while the 1.1 example moves to `examples/archive/workspace-1.1.json` and keeps every B062 check. `check_workspace2` (unique column and tab ids, a shown tab inside its column, an active column that exists, widths summing to one, profiles naming only columns, no pinned tab in a group) and `check_session` (the record lists exactly its workspaces, in order, and the active one is open) run over the examples and the `shell-commands` conformance fixture, whose two migration cases must be the archived 1.0 and 1.1 examples and whose 1.1 case must produce the 2.0 example. Fifteen negative cases cover a 1.1 document read as 2.0 and the reverse, a stored column number, a column without tabs, a shown tab from another column, a reused tab id, a missing active column, widths that do not sum to one, a profile naming an unknown column, a pinned tab in a group, a session whose active workspace is not open, an unknown tool, a text size step beyond the seven token sizes, a line spacing outside 1.35/1.5/1.7, a swatch that is not `#RRGGBB`, and an access key on a tab at schema and check level. The fixture kind `shell_commands` is known to `check_fixtures`.
