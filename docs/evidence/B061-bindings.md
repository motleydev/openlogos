## Decisions to review

- **`pub use native::UniFfiTag;` in `crates/ffi/src/lib.rs`.** uniffi's proc macros refer to
  `crate::UniFfiTag`, so with `setup_scaffolding!()` inside `native.rs` the tag must be
  re-exported at the crate root; this is one extra `#[cfg(not(target_arch = "wasm32"))]` line
  next to the agreed module line.
- **Additive change in `crates/conformance`**: `verse_map_from_rows(&[FixtureRow])` and
  `fixture_rows()` make the private row expansion usable by the binding (and by hosts that
  ship their own rows in the fixture shape). `run_versification` is unchanged.
- **`mapVerse` takes typed `rows: [VerseMapRow]`** (empty = the fixture table) rather than a
  JSON string: the host has the row shape in its own type system and the error names the
  offending row.
- **`selectionToAnchors` is plural and takes a `Paragraph`** (edition, revision, joiner,
  segments): a selection across verses yields one anchor per verse, as `split_selection` does,
  and the renderer knows the joiner it laid the segments out with.
- **`Reference.book` is the OSIS id string**, not a 66-variant enum: adding the deuterocanon
  then stays a core change, and hosts already have the id for display and storage.
- **Errors are non-flat** (fields cross the boundary): Swift gets
  `ReferenceError.UnknownBook(name:)`, Kotlin `ReferenceException.UnknownBook(name)`; the
  variant field is `reason` not `message` because Kotlin errors are `Throwable`s.
- **`anchorToUtf16(anchor, text)`** needs the segment text because an `Anchor` carries
  offsets, not text (specs/03); the host has the text it is rendering.
- **The scripts choose Xcode's clang per target** instead of changing `flake.nix`. The apple
  shell is `mkShellNoCC`, but the rust-overlay toolchain (`rust-default-1.99.1`) propagates a
  Nix `clang-wrapper` that appears first on `PATH` as `cc`, with `NIX_LDFLAGS` and
  `MACOSX_DEPLOYMENT_TARGET=14.0` set; host builds work with it, simulator builds do not. The
  flake's comment that the Darwin shells carry no compiler is therefore not true on this
  machine; a B002 follow-up should decide whether to strip the propagated compiler or to set
  the linker variables in the shell hook.
- **The XCFramework is linked, not copied, into `apps/apple/CoreHost/Frameworks/`**: SwiftPM
  resolves a `binaryTarget` path inside the package, and one copy under `artifacts/` is what
  the app will consume too.
- **Gradle has no wrapper**: Gradle and the JDK come from the Nix shell, so the pins are the
  flake's; the lockfile pins every Maven artifact.
