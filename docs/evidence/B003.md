# B003 evidence — select and clear a tiny initial corpus

Recorded 28 October 2026 on the owner's Mac mini (the B002 toolchain: Nix 2.34.4, Python 3.13.15
and git 2.54.0 from `nix develop .#pipeline`, jsonschema 4.26.0). Work was done in the git
worktree `openlogos-b003` (branch `b003-initial-corpus`) cut from `main` at 1872853. Nothing was
pushed by the agent; the lead opens the pull request and the owner signs by merging it.

**Decision basis.** The owner decided to acquire the whole licence-clean slate of specs/19 and to
flag, rather than exclude, anything whose provenance needs further research. This document and
the records under `rights/` are the agent's proposals; they are not legal clearance. Every
record is `status: "unknown"` with `reviewer: null`; signing means the human source steward
sets `status`, `reviewer` and `reviewed_at` in the record (the validator rejects `approved`
without both).

**Where the bytes are.** Every artifact is on the NAS, never in the repository:
`/Volumes/office-hub/openlogos/corpora/<source id>-<short name>/`, with a `MANIFEST.sha256`
beside the data (one `<sha256>  <path>` line per file, sorted, excluding `.git`). The SHA-256
of that manifest is the record's `artifact_sha256`; a copy of every manifest (all under 200 KB,
145 KB in total) is committed under `rights/<record>/manifest.sha256` and the validator checks
the copy against the hash. The NAS share cannot hold symlinks or a Python venv, so repositories
were cloned with `git init` + non-cone sparse checkout + `fetch --depth 1 --filter=blob:none
<commit>` (`core.fileMode=false`, `core.symlinks=false`), which also means only the listed paths'
blobs were ever downloaded. Local disk was not used for corpus bytes: `df -g /` was 4 GiB free at
the start, dipped to 2 GiB while a sibling worktree built (not B003's doing; the lead was told),
and was 4–5 GiB during the B003 runs. NAS usage at the end: 2.3 GiB in the fifteen directories
(43 TiB share, 30 GiB used).

## Commands

All inside `nix develop .#pipeline -c …` from the worktree, output captured to files, exit codes
echoed. Scripts lived in the session scratchpad; the two that matter for reproduction are
summarised here and the record generator is committed as `tools/b003_rights.py`.

```sh
# sparse-clone.sh <dest> <url> <commit> <pattern>...   (one pinned commit, only the listed paths)
git -C "$dest" init -q
git -C "$dest" config core.fileMode false; git -C "$dest" config core.symlinks false
git -C "$dest" remote add origin "$url"
git -C "$dest" sparse-checkout init --no-cone
git -C "$dest" sparse-checkout set "$@"
git -C "$dest" fetch -q --depth 1 --filter=blob:none origin "$commit"
git -C "$dest" checkout -q FETCH_HEAD

# downloads
curl -sSL -o bsb_usfm.zip https://bereanbible.com/bsb_usfm.zip        # and bsb_tables.xlsx, bsb.txt, terms.htm, downloads.htm
curl -sSL -o cross-references.zip https://a.openbible.info/data/cross-references.zip
curl -sSL -o institutes.xml https://www.ccel.org/ccel/c/calvin/institutes.xml   # and .txt, work page, copyright page
curl -sSL -o westminster3.xml https://www.ccel.org/ccel/c/anonymous/westminster3.xml   # and 2, 1; .txt; work pages
curl -sSL -o pg45001.txt https://www.gutenberg.org/ebooks/45001.txt.utf-8     # and 64392

# Git LFS objects (no git-lfs in the shell): POST the pointer's oid and size to
# https://github.com/<owner>/<repo>.git/info/lfs/objects/batch, download the returned href,
# verify SHA-256 == oid, replace the pointer file.

# manifests: python3 -I manifest.py <dir>...  writes MANIFEST.sha256 (sorted, excludes .git)
# records:   python3 -I tools/b003_rights.py /Volumes/office-hub/openlogos/corpora
# validator: python3 tools/validate.py
```

## Acceptance, item by item

1. **Three Bible/source-language editions with explicit coverage and one ancient edition have exact artifact/rights records** — met for the Bible editions (BSB, SBLGNT, OSHB/WLC, plus N1904 and the MACULA layers, each with a manifest hash, a licence hash and declared coverage); **partial** for the ancient edition: Calvin's Institutes and the Westminster standards have exact artifact records, but the Beveridge and Westminster artifacts are CCEL editions flagged for digitization rights and (Confession) edition, and the only licence-clean Institutes found is the Allen translation (S75), not the Beveridge one named.
2. **No ESV or unknown-rights bytes in fixture imports** — met. The conformance fixtures cite SBLGNT, BSB, WLC and CC0 content only; the validator now rejects a fixture whose licence, source or description names ESV or NIV. On the NAS, the first Clear-alignments checkout, which contained a Lexham English Bible verse file from the legacy folder, was deleted and re-cloned without it; the OpenBible file holds references and votes, no verse text.
3. **Human source steward signs acquisition decisions or substitutes source** — pending by design: every record is `unknown` with a `steward_proposal`; the owner signs by merging and may set `status`, `reviewer`, `reviewed_at` per record (the validator enforces the pairing).
4. **Clear an exact baseline cross-reference artifact and declare its coverage; no proprietary screenshot-derived data** — met: OpenBible `cross-references.zip` of 2026-10-26, 344,799 rows over 66 books, CC BY 4.0 from the page captured beside it; nothing screenshot-derived anywhere in the slate.
5. **Prefer the licence-clean defaults; flag BHSA, Louw-Nida columns and share-alike layers as restricted modules** — met: BSB, SBLGNT, WLC/OSHB, MACULA CC BY layers, Clear alignments and OpenBible are proposed clear; BHSA (CC BY-NC), the UBS dictionaries (CC BY-SA) and MorphGNT (CC BY-SA) are restricted modules; the Louw-Nida `ln`/`domain` columns and the SDBH columns in MACULA carry `restricted_module` flags; the validator rejects a restricted module marked redistributable.
