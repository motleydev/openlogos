## Decisions

Each is a line of code a reviewer can change; a change is a new layer revision.

1. **A separate overlay**, `~/.cache/openlogos/alignments`, one layer per testament
   (`clear-sblgnt-bsb`, `clear-wlc-bsb`). A layer's revision names the S55 commit and both text
   pack revisions (`clear-wlc-bsb-c99bd0a-on-oshb-wlc-4.20-3d15126-bsb-2026-03-08-64a7130`). The
   text packs and morphology layers are not changed.
2. **The record is Clear's record.** One layer record per Clear record, never split or merged:
   many-to-many and discontinuous groups stay as they are. Clear's id and its `meta` are kept as
   given; every record says `origin: manual`, `status: created` (all 385,406), so every answer is
   labelled manual. The layer adds the specs/03 origin `curated:clear-alignments@c99bd0a`;
   status `aligned`, confidence none.
3. **Unaligned is not null.** Clear has no record with an empty side. A word in no record is
   `unaligned` in every answer; nothing is invented to say "explicitly null".
4. **English: same letters, cut differently.** The pack's BSB is `bsb.txt` verbatim, tokens are
   whitespace fields with attached punctuation (B071 decision 6); Clear cuts words from
   punctuation and marks where no space follows. Per chapter, both sides become one character
   stream with all whitespace removed. Equal streams pair character for character (250 of 260 NT
   chapters, 919 of 929 OT). Otherwise a Myers shortest edit script pairs the characters that
   stay. A Clear word joins only if every character is paired, inside one pack token, contiguous;
   its scalar range in that token is kept. Nothing is matched by similarity.
5. **English classes**, first that applies from the bottom up: `exact`; `punctuation` (the token
   is the word plus attached punctuation, `Son,`); `shares_token` (the token holds two or more
   Clear words, `ground—because`); `token_has_other_letters` (none occurred); `other_verse`
   (Clear's verse is not the pack verse: a Psalm title the pack keeps in verse 1);
   `in_changed_verse` (joined, in a verse whose letters differ). Not joined: `text_differs`,
   listed. A pack token with no joined word: `not_in_clear_target` (or
   `verse_not_in_clear_target`, which did not occur), listed.
6. **Psalm titles fall out of decision 4.** Clear numbers all 116 BSB titles verse 0; the pack
   does for 63 (B071 decision 5) and keeps 53 at the start of verse 1. Chapter streams make that
   the same run of letters: the 63 join `exact`, the 53 titles' 222 words join `other_verse`.
7. **Original language: by id.** Clear's source tables are MACULA's words and morphemes under
   MACULA's ids (`n40001001001`, `o010010010011`); the B026 layers keep that id for every
   morpheme. So the join is the id; the letters are then classed, never used to choose:
   `exact`; `normalization` (NFC, John 7:53–8:11); `accents_omitted` (Clear's WLCM table has no
   cantillation, meteg or rafe); `movable_letter_omitted` (`οὐ` for `οὐκ`/`οὐχ`);
   `elision_omitted` (`ἐπ` for `ἐπ᾿`); `punctuation_omitted` (`εἰσιν` for MACULA's `εἰσιν;;`,
   John 8:10); `no_pack_token` (the morpheme has no token in the pack); `surface_differs`
   (would not be joined; none remain).
8. **Source words are morphology layer positions.** So a Clear record over `בְּ` + `רֵאשִׁית`
   names `wlc:01001001001a` and `…b`, the morpheme ids B026 minted, and the lemma and gloss come
   from the layer. The layer revision is in the manifest; a different one makes
   `renderings` refuse the edition (named in `unavailable`) and `align` answer without
   morphology, because the positions would mean other morphemes.
9. **Morphemes Clear does not have** are listed as `not_in_alignment_source`: all 6,435 are the
   articles B026 adds where a prefix's vowel implies one (WLCM has 469,476 rows, the layer
   475,911).
10. **Tokenization hashes** of both sides are computed from the text packs exactly as specs/03
    defines them and kept in the manifest (the packs do not declare one). `alignment_set` exports
    any verse range as a `core::identity::AlignmentSet` that `validate`s and carries them; a word
    with no token cannot be stated there and is counted as omitted.
11. **Renderings** count occurrences (morphemes) of the matched lemma in the scope: the
    denominator. Each aligned occurrence's rendering is the BSB words of its record(s) in
    reading order, `…` between runs, case kept (`Word` in John 1 stays apart from `word`). A row
    counts how many of its occurrences share the record with other source words (so `the Word`
    for `ὁ λόγος` is visibly a group's rendering). Unaligned occurrences are the last row;
    occurrences outside the alignment's source are `not_covered`. Lemma matching is B026's
    (exact if spelled as a lemma, else by key), homographs stay separate tables. Every answer
    carries the note that renderings are evidence of translation choices, not definitions.
12. **Strong's numbers play no part** in any join or answer (B065, B026): the source side is
    keyed by token ids from MACULA ids; the Strong's shown is the morphology layer's.
13. **Size.** Target texts, join classes and metadata are stored once (`string` table); record
    members are little-endian `u32` blobs; external ids are kept as text, which is most of the
    size (below).

## Not verified, and open

- **No context-menu row yet; the plan for the host phase is agreed.** `nav.original_word`
  ("Original word") is registered, host-performed, and gated on the session's `data_layers`
  (`alignments`, added by `use_alignments` / `useAlignments` beside any other layer): disabled
  with "Needs the alignment import" until then, "Needs a passage" without a reference. It is
  reachable from the palette and by invocation. A thirteenth row on a BSB word is not possible:
  the word menu already has the twelve top-level rows specs/22 §4.2 allows (the core test and the
  conformance shape check both refuse 13). The lead's ruling: in the host phase, on a translation
  word, the slot of the always-disabled "Word study" row becomes the aligned original word,
  reusing the `word-study` icon, so no new host asset is needed. It is not done on this branch
  because no host calls `useAlignments` yet, so the command would be disabled everywhere and
  changing the shared context-menu fixture now would only churn every host's conformance run.
- No host draws an alignment (the host phase). The scalar-to-token step for a selection is the
  host's, as for B026.
- The statistical aligner and its scoring against these records (B067's other half) are not
  done.
- In a changed verse the character diff can leave an equal word unjoined (Matt 10:9 `any`);
  listed. 31 Clear words and 37 pack tokens in 22 verses are not joined.
- A source token's morphemes that Clear lacks (the implied articles) are listed in the layer but
  not shown in a token answer's words.
- Memory on an iPad or Android device was not measured; the alignment layers add about 69 MB to
  the morphology layers' 90 MB in a browser.
