## Data and licenses

No work text is committed. The fixtures are structural: citation strings (CC0, written for
the fixtures) and section-map rows (locator → invented segment id) for four public-domain
works: the Westminster Confession of Faith (1647), the Larger and Shorter Catechisms,
Calvin's *Institutes* in the Beveridge (1845) and Allen (1813) translations, and Thayer's
*Greek-English Lexicon of the New Testament* (1889). The Battles translation (1960) is in
copyright and is not a grammar target or a fixture edition. The one quoted phrase in the
catalog fixture ("the whole counsel of God … is either expressly set down in Scripture") is
WCF 1.6, public domain. Synthetic bench data (seeded xorshift) lives under the scratch
directory and is deleted after the run.

## Benchmark

subcommand is `openlogos-retrieval-bench b068 <dir> --packs 200 --edges 1000000`; 1M edges
rather than B064's 5M keeps the scratch set (packs plus two link-index files) under the 1 GB

packs; two fresh builds from the same installed set (the second from the reversed list) with

first pack; in-place rebuild keeping three user edges; `cited_count` rows; `most_cited` from
the count table against the B064 `GROUP BY` path with an agreement check; backlink counts,
backlinks, chains and `cited_target` latencies.

## Decisions to review

- **Crate placement.** The link index and the new catalog stay in `crates/retrieval-sqlite`,
  not `crates/package` as specs/19 item 3 says. Reason: both are SQLite artifacts reached
  through `RelationStore` and the engine's connection code; `crates/package` has no engine
  dependency and no code yet, and giving it `rusqlite` now would only duplicate the engine's
  storage handling. The device layout the spec asks for (one mutable database beside the user
  database, plus a small catalog) is what ships; moving the two modules into `package` later is
  a file move. Recorded in the specs/19 subsection.
- **Catalog as a separate file.** `catalog.sqlite` is the installed set (pack ids, paths,
  SHA-256, work, edition, canonical scheme, rights access, copied `section_map` rows);
  `links.sqlite` is derived from it and can be deleted and rebuilt. Keeping them apart makes
  "rebuild from the installed set" a pure function of the catalog and lets the byte-identity
  test compare whole files.
- **Locator string rule.** An edge's `dst_locator` is bare in the work's canonical scheme and
  `scheme:locator` otherwise (`thayer-1889-pages:p.6`), so `Locator { work, locator }` did not
  grow a third field. A work has exactly one canonical scheme (validator check).
- **Catechism form.** `Q. 1`, `Q1`, `Question 1` and a bare `1` all canonicalize to `wlc:1`
  (the question-and-answer unit); `A. 1` is `wlc:1.a`. A `1.q` part is not produced.
- **Page marker required.** `Thayer 6` is unparsed (`missing_locator`); only `p.`, `pp.`,
  `page`, `pages` introduce a page. A bare number after a lexicon name is too ambiguous.
- **`Edge` grew `method` and `review_state`** (serde defaults keep older JSON readable);
  the pack `edge` table gained `review_state` and `context`; `PACK_SCHEMA_VERSION` is `b068-1`
  and the engine refuses `b064-1` packs, so B064's scratch N1904 pack must be re-ingested.
- **Documented basis** = provenance not model similarity, non-empty `method`, review state
  source-attested, reviewed, published or disputed. `proposed`, `rejected`, `superseded` and
  `retracted` edges are not followed by chains. The start node appears as an empty chain when
  one of its own hops is undocumented, so the UI can show the untaken edge.
- **Bible editions in the catalog** (no `locator_scheme` in the manifest) resolve any verse
  locator as `equal`/`direct` when installed; which verses an edition prints is the verse map's
  job (B006), not the catalog's.
- **Higher-level citations** (`Institutes 3.2`) resolve through their subsections with a
  labeled basis. This is a fallback the spec did not name; it is labeled, never silent.
- **`backlink_count` now reads `cited_count`**, so it is O(1) on hubs; `most_cited` reads the
  same table (B064's recommendation). The table has one row per (destination, relation) plus
  one "any relation" row per destination.
- **`sha2` is a new pinned dependency** of `retrieval-sqlite` (not of core); no SHA-256
  existed in the workspace (B006's tokenization hashes are computed by the pipeline).
- **API_VERSION 0.1.2** per the additive-change rule; the Swift and Kotlin host test literals
  were edited but not run (apple and android shells not entered).
