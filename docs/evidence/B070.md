## The model (specs/22 §2)

```
Session      schema_version 1.0, workspaces[], active_workspace_id, tool, next_serial
Workspace    schema_version 2.0, id, title, columns[], active_column_id, notes_dock,
             layout_profiles (per class: visible_column_ids, widths, notes_dock_open), next_serial
Column       id, tabs[], shown_tab_id, width_fraction
Tab          id, kind, content_id, content_revision, reference, scroll_anchor,
             link_group | pinned, history (PaneHistory from B040, persisted when non-empty)
```

Column numbers are positions and are never stored (the schema rejects a `number` field). The
active tab is the active column's shown tab. Ids are minted as `t{n}`, `c{n}`, `w{n}` from a
per-record serial that skips ids in use, so no id is minted twice. Link groups are resolved
over every tab of one workspace, shown or hidden, through `navigation::followers_among` (the
B040 rule, now shared by panes and tabs); a navigation also moves every tab in follow mode
(unpinned, no group), and `Effects.followed_tab_ids` names them so a host can remap a follower
whose resource uses another versification.

## Decisions to review

1. **New schema file, old one kept.** ADR 0003 says a MAJOR bump is a new line with its own
   schema file and the old file stays while a reader needs it. 2.0 is
   `schemas/workspace-2.schema.json` (`$id …:workspace-2`); `schemas/workspace.schema.json`
   still describes 1.0 and 1.1 and validates the two archived examples. The session record is
   its own schema at 1.0.
2. **Which 1.x arrangement becomes the columns.** A 1.1 workspace has up to four class
   profiles but 2.0 has one column structure. The migration takes the widest stored profile
   (ultra-wide, wide, regular, compact), or the pane order when there is none. Each visible
   pane becomes a column; the visible members of a collapsed link group share one column; the
   tab-order panes become tabs of the last column (specs/22 §2). Every stored profile is kept as
   a column profile naming the columns of its visible panes, so "the iPad shows panes 1–3" is
   preserved as "the iPad shows columns 1–3".
3. **What "lossless" covers.** Pane ids (as tab ids), kind, resource, revision, passage, link
   group, pinned state, scroll anchor, the active pane, the notes dock note and each class's
   visible set are carried exactly. The unit tests migrate both examples, export back to 1.1
   and compare every pane fact plus `derive_profile` on every class at five widths. Two things
   are not carried: a 1.x pane's own `width_fraction` when a profile sizes the columns (no 1.1
   reader reads it, `derive_profile` ignores it), and, when the active pane was a tab-order
   pane, a class *without* a stored profile borrows the order with the active pane where rule 4
   already put it on the stored class. Both are in the test comments.
4. **Undo covers changes, not focus.** Every layout command and navigation (go to passage,
   back, forward) returns an undo record; focus changes (switch workspace, focus column, next
   tab, go to tab) and tool changes do not, so ⌘Z takes back what the reader changed rather
   than where they looked. Undo restores the touched workspaces and the active workspace, so
   undoing a rename made in another workspace returns there.
5. **New tabs copy the active tab.** New tab, new column, new workspace and duplicate copy the
   active tab's resource, passage, anchor and link mode under a new id with an empty history.
   A passage opened with ` @new` is the exception: its tab is pinned, so it does not drag its
   group along.
6. **Commands the host performs.** Selection highlight/collect/study, the collection and study
   drawers, text size, theme, focus mode, the tool palette's visibility, swap swatches,
   export and focusing the palette are registered (with shortcuts and disabled reasons) and
   return `handled: false`. The notes dock and the six tools are core state.
7. **Shortcuts.** specs/22 §6 as data: ⌥ defaults identical on web and Mac, native aliases
   (⌘1…⌘9, ⌘T, ⌘W, ⌃Tab, ⌘⇧N) only on Mac and iPad, `{n}` for a column-number family, bare
   keys V H P M E C X and `/` flagged `bare_key`. The specs/21 §9 bindings §6 does not replace
   (back/forward, pin, link, the selection commands, collection drawer, focus mode, undo) are
   kept; its ⌘⇧N for the notes dock is dropped because §6 gives ⌘⇧N to New workspace. A unit
   test asserts no shortcut is bound twice on a platform.
8. **Ranking** (documented at the head of `palette.rs`): equal 1000, prefix 900 − extra length,
   word prefix 800 − 10 per earlier word, all query words as word prefixes 700, substring 600,
   in-order subsequence 300 − gaps; aliases −30, keywords −100 and only from 600; a title or
   alias followed by an argument 950 with the argument filled in; a trailing number fills a
   column argument. Ties: enabled before disabled, then registry or session order. Tabs also
   match the book's full name (`@genesis` finds `Gen 1:1`) and score 800/600 when the query is
   a passage in the same chapter/book. The Text section keeps the provider's order.
9. **Text provider.** `palette::TextProvider` is a Rust trait; the bindings offer only the
   conformance fixture provider (`ShellHandle.fixture()`, `useFixtureText()`). B071 adds the
   real search; exposing a host-implemented provider through UniFFI (a foreign trait) is left
   to it.
10. **Bindings shape.** One stateful `ShellHandle` per window in both bindings, so the palette
    index lives next to the session and the session is not marshalled on every keystroke.
    UniFFI returns view records (`ShellSession` → `ShellWorkspace` → `ShellColumn` with its
    `number` → `ShellTab`) plus the persisted records as schema JSON; wasm returns the core's
    serde shapes. The UniFFI error is `ShellCommandError` with `detail`, `command_id`, `kind`
    and `reason` fields (no `message` or `cause`).
11. **Wasm size.** `openlogos_ffi_bg.wasm` after `wasm-opt -Oz` is 1,812,637 bytes (515,929
    gzipped) against 1,364,621 (381,342 gzipped) at fe566e9: +448 KB, +135 KB gzipped. About
    44 KB of that is the fixture JSON embedded twice by `crates/conformance` (as every fixture
    is); the rest is the new code and its serde-wasm-bindgen (de)serializers. The pinned shells
    carry no twiggy, so the split is not measured; worth a look before the web shell ships.
12. **Performance fixes made during the bench** (reasons in `ca94cc6`): `Shell::apply` mutates
    in place and copies only the workspaces an undoable command touches (every command had
    been cloning the whole session, 36 µs and growing with history); tab history keeps 100 back
    visits; the palette index reads `Book.C.V` tab references without the alias table (index
    build 5.0 ms → 0.16 ms).

## Second follow-up: reason wording and short references

- **Disabled reasons are words.** "Go to tab" showed "Needs tab_id". `DisabledReason`'s text is
  now always plain words: a missing argument reads "Choose a tab", "Choose a workspace",
  "Needs a column number", "Needs a passage", "Needs a value", "Needs a scroll position" or
  "Needs a name or value", and an unknown workspace or tab reads "That workspace (tab) is not
  open" instead of echoing its id. The `kind` tag stays for code. The fixture asserts the
  exact text for ten commands and that no reason a reader can see contains `_`: every
  disabled command on the fixture session with and without a selection, every disabled
  scenario step and every disabled palette row.
- **Short references.** `ReferenceSet::to_short` (crates/core) uses
  `AliasTable::english_short()`: the SBL display names, with the Gospels and John's letters as
  `Mt`, `Mk`, `Lk`, `Jn`, `1 Jn`–`3 Jn`; every short name is an alias, so a label parses back.
  `formatShort(reference)` takes the citation as text in UniFFI and wasm (`Jn 3`, `Jn 3:16`,
  `Gen 1:1–2`). Palette tab and text rows now read `resource · short reference`.
- **Resource names.** The core does not know that `bsb` is "BSB", so the host registers names:
  `ShellHandle.setResourceTitles` (UniFFI map, wasm object), held on the session at run time
  (not persisted) and bumping the revision. Rows use the name, else the id; tabs also match on
  the name, and on the row title so words can span resource and passage (`@sblgnt jn`). The
  UniFFI `ShellTab` gains `resource_title` and `reference_label` (short form).
- shell-commands grows from 215 to 236 cases; every host runs 1195. The passage row keeps
  the display form (`John 3:16`).

## Third follow-up: reason text through the bindings, plural counts

- **Reason text for hosts.** `PaletteItem` and `CommandState` carry `disabled_text` beside the
  `disabled` reason, so the wasm surface returns the words ("Choose a tab") with every disabled
  palette row and command; a failing `apply`, `undo` or `redo` in wasm throws an `Error` whose
  `reason_text` holds them (its `kind` and `details` are unchanged). UniFFI already returned
  text: `ShellPaletteItem.disabled_reason`, `ShellCommandInfo.disabled_reason` and the
  `reason` field of `ShellCommandError.Disabled`. Fixture rows assert `disabled_text`.
- **Counts read as words.** The workspace row's subtitle is "Workspace · 1 column, 1 tab", not
  "1 columns, 1 tabs".
- **Passage row unchanged.** It keeps the display form as its title ("John 3:16") and the target
  as its subtitle ("Open in column 2"). Adding the short form as well would repeat the
  title in other words; the row confirms what was typed, so it reads best in full.
- shell-commands grows from 236 to 240 cases; every host runs 1199.
