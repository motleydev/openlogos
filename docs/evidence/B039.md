### The portable record and the renderer

A stroke is stored as sampled points (`x`, `y`, `pressure` or `null`, `elapsed_ms`) with
its tool, colour, opacity, width and a `brush_version`; the outline is never stored. A
renderer looks the brush up by version (`Brush::for_version`), re-derives the outline from the
points with the core's `inkOutline`, and fills it **once** with the non-zero winding rule at
the stroke's opacity. That is the highlighter rule of specs/13: a self-overlapping outline is
one fill, so it never darkens over itself; two strokes are two fills and accumulate. A stroke
whose brush the build does not know (a PencilKit stroke, a future `pen-2`) is drawn by the
tool's current brush and flagged `exact_brush: false`, which the host must label ("Shown from
portable strokes"), so a brush change can never silently reshape an older note.

The three hosts render the same way: `CAShapeLayer` per stroke (`fillRule = .nonZero`,
`opacity`) on Apple, `ctx.fill(path, "nonzero")` with `globalAlpha` on the web.

### Palm rejection and gesture arbitration (rules, tested)

`crates/ink/src/touch.rs` is the rule set; the JS (`ink.js`) and Swift (`InkTouchPolicy`)
mirrors run the same seven cases by name. Decisions are made when a contact begins and are
remembered for its life:

1. A stylus always draws in the canvas; it cancels a finger stroke in progress and takes over.
2. **While a stroke is in progress, a finger landing anywhere, another pane included, is the
   hand: ignored for its whole life, even after the pen lifts.** The live page case puts a
   touch on the reading pane mid-stroke and checks `scrollTop` did not move (`scrollTop_before
   40, scrollTop_after 40`); on the web the page also cancels `touchmove` while a stroke is in
   progress, since a browser scroll would otherwise not consult the page.
3. A contact whose major radius is ≥ 20 pt at `began` is a palm regardless of mode.
4. Stylus mode: a finger in the canvas does nothing; elsewhere it scrolls its pane.
5. Finger mode: one finger draws in the canvas; a second finger during that stroke is ignored.
6. A pointer (mouse, trackpad) draws in the canvas and scrolls elsewhere; there is no palm.
7. A cancelled or ended stroke releases the canvas.

Rust: 7 tests in `touch::tests`; web: `6/6 palm cases passed, live palm case passed`; Swift:
6 cases in `InkTests` plus the engine test. **Finding from the XCUITest run:** the simulator's
system touches report a `majorRadius` above 20 pt, so the default rule called the first drag a
palm (`readout: finger ignored: largeContact`, `ipad-uitest-3.log`). The threshold is a
constant to calibrate on a device (`UITouch.majorRadius` of a fingertip is documented as a
few points); `-OPENLOGOS_INK_PALM_RADIUS` overrides it for the simulator and the UI test records
the simulator's value first (section 5).

## 5. Acceptance 3: native adapter export limits

### PencilKit (probe in the simulator; `PencilKitProbe.swift`, `ipad-pencilkit-1024-demo.png`)

`PKCanvasView` with `drawingPolicy = .anyInput` (no Pencil in the simulator), the system pen
and marker, the vector eraser. A programmatic `PKDrawing` (a marker band and a pen stroke built
from `PKStrokePoint`s with force and tilt) and an XCUITest finger drag were exported through
`inkDocumentJson`: valid, `3 strokes, 165 control points` (`pencilkit-export.txt`). On the 1.1
build the export carries the tilt: `tilt on 2 strokes (recorded as altitude/azimuth, schema
1.1; null elsewhere)` and 60 control points with `"altitude": 1.047…` and `"azimuth": 0.785…`
for the programmatic pen stroke, `null` for the marker (`ipad-pass-applog.txt`).

What PencilKit exposes per stroke and where it goes:

| PencilKit | Our record |
|---|---|
| `PKStrokePath` control points: `location`, `timeOffset`, `size`, `opacity`, `force`, `azimuth`, `altitude` (also `interpolatedPoints(by:)`) | `points[]`: `x, y` through `stroke.transform`; `elapsed_ms = timeOffset × 1000` (made monotonic); `pressure = force / 4.1667` when any force > 0, else `null`; `altitude` clamped to `0…π/2` and `azimuth` folded into `0…2π` when any control point of the stroke reports a non-zero angle (PencilKit writes 0 for a finger), else `null` (schema 1.1) |
| `PKInk.inkType` (`pen`, `pencil`, `marker`, `monoline`, `fountainPen`, `watercolor`, `crayon`), `color` | `tool`: marker → `highlighter`, the rest → `pen`; `brush_version = "pencilkit/<inkType>"` (not one of ours, so re-rendering uses the labelled fallback); `color` resolved for light mode; `opacity` from the colour's alpha and the mean point opacity |
| `size` per point | `width` = mean `size.width` |
| `mask` (`UIBezierPath?`, the bitmap eraser's result) | not representable; the stroke is kept whole and the count of masked strokes is reported |
| `randomSeed`, `renderBounds`, `PKInk.requiredContentVersion` | not stored |
| `PKDrawing.dataRepresentation()` | the opaque native fidelity blob (1,539 bytes for two strokes, 2,747 for three); it round-trips through `PKDrawing(data:)` only. Kept beside the record as the optional cache specs/13 allows, never the only copy |

What PencilKit does **not** expose: the raw `UITouch` samples (coalesced, predicted) behind a
stroke, only its resampled B-spline control points (`not raw touches`); the brush geometry
(how an ink turns points into pixels; our fallback brush re-renders the points, so the look
differs); the unit of `force` (undocumented; `UITouch.maximumPossibleForce` on Pencil is
4.1667 and the export states this assumption); the blob format; the eraser as operations (only
the resulting mask); absolute timestamps beyond `creationDate` + offsets. Finger and simulator
input report force 0, so pressure is `null` there, not 0.5, and altitude and azimuth 0, so tilt
is `null` there too.

### Android Ink API (from documentation only; no build, no device)

Jetpack `androidx.ink` (alpha line, Apache 2.0; module and version numbers unverified here):
`ink-authoring` (`InProgressStrokesView`, front-buffered low-latency rendering of the stroke
in progress from `MotionEvent`s, including predicted and historical samples), `ink-strokes`
(`Stroke`, `StrokeInputBatch`, `StrokeInput` with `x`, `y`, `elapsedTimeMillis`, `pressure`,
`tiltRadians`, `orientationRadians`, `toolType`, `strokeUnitLengthCm`; absent sensors are
NaN/unset), `ink-brush` (`Brush` = `BrushFamily` + size + epsilon + colour; stock families are
**versioned**, e.g. a `pressurePen` and `marker` v1), `ink-geometry` (the stroke's
`PartitionedMesh`, intersection and bounds), `ink-rendering` (`CanvasStrokeRenderer`),
`ink-storage` (serialisation of input batches and brushes, gzip-compressed protobuf; the stroke
mesh itself is not the storage form, it is regenerated from inputs + brush).

Mapping: the raw input batch is exactly our `points[]` (pressure and tilt included, the 1.1
`altitude`/`azimuth` fields; the API's tilt and orientation are radians as ours are); the stock brush family and version is a `brush_version`
(`androidx.ink/pressure-pen-v1`), opaque geometry like PencilKit's, so re-rendering elsewhere
uses our fallback; colour, size, opacity are on the brush; the eraser is the app's (no mask
primitive); ids and z-order are the app's. Unlike PencilKit it exports the raw samples, so an
Android stroke round-trips into the portable record without resampling, and the native cache is
the serialised batch + brush, not a bitmap format. Unverified: everything above beyond the
module names, until a build.

## 8. Decisions to review

1. **Engine: perfect-freehand as the core's own geometry (`crates/ink`), not an npm dependency
   on any host.** The port is 5e-7 from upstream and the wasm, UniFFI and (later) Kotlin hosts
   all call the one implementation; a brush change is a new brush id. Review: whether to keep
   the V8-`hypot` emulation (chosen so the golden vectors are byte-comparable) or accept
   platform `hypot`.
2. **Excalidraw is not the editor.** It is a fine import/export target (open JSON) and could be
   offered as "open in Excalidraw" for a sheet, but it cannot be the margin layer. Review: drop
   the comparison bundle after this task (it is gitignored output; the page and lockfile stay
   small) or keep `just ink-excalidraw-build` for interoperability tests.
3. **Brush options are mirrored in JS and Swift.** The binding exposes `inkOutline` and
   `inkDocumentJson`; the brush registry (`brush.rs`) is Rust-only, so the two hosts carry the
   same two option sets by hand. Review: a third binding function (`inkRenderPlan(document)`)
   returning the composites, so hosts stop mirroring; it was left out to respect the "at most
   two additive functions" bound.
4. **Schema 1.1 adds tilt** (done at the orchestrator's request): nullable `altitude`
   (`0…π/2`) and `azimuth` (`0…2π`) radians per point, required keys in a 1.1 file and
   forbidden in a 1.0 file; the 1.0 example is archived and `crates/ink` reads 1.0 with `None`
   and writes 1.1 (ADR 0003 `older_minor`). The UIKit canvas records `altitudeAngle` and
   `azimuthAngle(in:)` for a Pencil, the web page `PointerEvent.altitudeAngle`/`azimuthAngle`
   for a pen, and both store `null` for a finger or mouse. Review: a pen whose angles never
   leave the spec defaults (π/2, 0) is treated as no sensor on the web, like constant pressure.
8. **Force normalisation assumption.** `PKStrokePoint.force` has no documented unit. The
   export divides by 4.1667, the `UITouch.maximumPossibleForce` of an Apple Pencil, clamps to
   `0…1`, and says so in its notes; if PencilKit's force is already normalised the stored
   pressure is 4.17× too low and a device run with a Pencil (compare `UITouch.force` on the
   same stroke) settles it before any PencilKit import ships.
5. **Palm threshold.** 20 pt is a guess; the simulator's touches exceed it. The device run
   should log `majorRadius` distributions for fingertip and palm before fixing the constant.
6. **Pressure placeholders are null.** A pen whose pressure never varies over a stroke, and
   any mouse or finger, stores `null` (specs/13 "null, not fabricated"), at the cost of a
   genuine constant-pressure pen stroke losing its one value. Review.
7. **`tools/validate.py` and the nixfmt check now skip build output** (`node_modules`,
   `target`, `artifacts`, `dist`, …): a vendored package shipped an `AGENTS.md` and another a
   `flake.nix` that tripped `just lint` once node_modules existed.

## 9. Skipped and not done

- No stylus, iPad, Android device or Pencil: nothing hardware-measured; the target stays open.
- Excalidraw RTL: the locale chunk did not apply in the esbuild bundle; not debugged further.
- The Mac canvas takes tablet pressure from `NSEvent.pressure` only for tablet events; no
  tablet was available, so that path is untested.
- Selection/lasso, move/resize, pan/zoom of the sheet (specs/13 requirements) are not in the
  prototypes; pixel erasing is absent and explicit.
- Persistence during a stroke and recovery after interruption are not built; the record is
  in memory.
- Firefox and Safari runs of the ink page were not made (the runner takes the same
  `--browser` switches as B005's).
- Kotlin host: no binding host test for `inkOutline` (no Gradle run here); the Swift CoreHost
  was not given an ink case either, the app's `InkTests` cover the Swift side.
- The iPad palette at 1024 pt is a horizontal scroller: the colour picker now fits, the width
  slider sits past the right edge and the "Stroke eraser" segment truncates. The Mac shows
  everything at 1440.
