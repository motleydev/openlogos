key moved, as instructed. The orchestrator and owner decide when; it is required before any

## 6. Nix shell fix (which of the two options was taken)

Option "fix the shell in flake.nix" was taken, not per-script workarounds. Finding: the apple
shell already used `mkShellNoCC`, yet `command -v cc` inside it was
`/nix/store/…-clang-wrapper-21.1.8/bin/cc`, because rust-overlay's rustc propagates the Nix
clang wrapper and cctools; their setup hooks also export `CC=clang`, `LD=ld`, `AR=ar`, …,
`MACOSX_DEPLOYMENT_TARGET=14.0`, `NIX_CFLAGS_COMPILE`, `NIX_LDFLAGS`. xcodebuild reads
environment variables as build settings: with `LD=ld` present the simulator link failed with
`ld: -objc_abi_version '-Xlinker' not supported (expected 2)`. The hook now removes
`/nix/store/*-clang-wrapper-*/bin`, `/nix/store/*-clang-[0-9]*/bin` and
`/nix/store/*-cctools-*/bin` from `PATH` and unsets those variables, in every Darwin shell.
After the change, inside `.#apple`: `cc=/usr/bin/cc clang=/usr/bin/clang ld=/usr/bin/ld
lipo=/usr/bin/lipo`, none of the tool variables set. `scripts/apple-bindings.sh` keeps naming
Xcode's clang per target explicitly (harmless, and it documents why).

Proof that the bindings lane still passes after the change, `nix develop .#apple -c just
test-swift` (cargo cached; the first run of the session, before the change, compiled the three
targets in 41 s, 11 s and 21 s and ran `swift test` in 21 s), last lines:

```

   swift test: 15s
exit=0
```

## Decisions for the orchestrator to review

1. The Darwin-shell `PATH`/environment scrub in `flake.nix` applies to every Darwin shell
   (`core`, `web`, `android`, `pipeline`, `ops`, `apple`), not only `apple`: the flake's own
   comment already claimed the shells carry no compiler, and `just ci` in `.#core` now links
   with `/usr/bin/cc`. Linux shells are untouched.
2. The generated `OpenLogosCore.swift` is compiled into the app module (no `import`), rather
   than wrapped in a framework target. One copy, simplest project; B062 may prefer a module.
3. The shelf is a separate Tailscale Serve entry on HTTPS 8767, not a path under
   sudoku-color's 443 (Serve does not strip path prefixes, and a path would tie the two).
4. `ship.sh` does not bump or commit a version (sudoku-color's does): a build-script commit
   from an agent worktree contradicts the one-task-per-branch rule, and `CURRENT_PROJECT_VERSION`
   (UTC `yyjjjHHMM`) already makes every build unique.
5. `shelf-install` and the first `ship ios` were run in this session, so the Mac now has a
   launchd agent `org.openlogos.shelf`, a Serve entry on 8767 and one build on the shelf.
   `just shelf-uninstall` reverses the first two.
6. `OpenLogosMac` target exists in `project.yml` but was not built or run in this session; the
   lanes are iOS/iPadOS.
7. No source citation was added; no new `[Sxx]` ids.
