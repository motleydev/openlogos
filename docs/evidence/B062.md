## How the review was done

**Display classes.** No physical iPad, Mac, iPhone or external display was used, and the lead's
rules allowed none. The display-class table in specs/18 lists the published logical sizes
(points) of the current iPhone widths (375, 390, 393, 402, 430, 440), the iPad mini, 11-inch and
13-inch classes in both orientations, Slide Over, Split View thirds and halves, Stage Manager
windows and external displays, the MacBook Air and Pro defaults, the Studio Display and Pro
Display XDR at their default scaling, 3440 × 1440 and 5120 × 2160 at 1×, and the 320 CSS px
WCAG reflow width. For each the table gives the class the width selects, the derived pane
count at standard and accessibility text, and a "verified how" column. Only four widths carry
a rendered measurement, all from B004 on the iPad simulator with viewport overrides (1440 × 900
scaled, 1024 × 768, 768 × 1024, 390 × 844; docs/evidence/B004.md); every other row says
"published size; not rendered". Review findings that changed the matrix: the iPadOS pane row
("3 landscape / 2 portrait") became width-derived, since the 13-inch iPads show three panes in
portrait (1024 pt, which B004 rendered) and the 11-inch class and mini show two; iOS gained the
keyboard launcher with a hardware keyboard (specs/21 §9 already provided it); the web row's pane
count became 1–6.

**Derivation rules.** Written from specs/12's content minimums (340 pt at standard text, from
B004's 341-pt panes at 1024), B004 decision 3 (480 pt at accessibility sizes), specs/16's
measure (640 pt cap, B004) and specs/21 §4 and §10 (tabs under the identity row, the dock as a
pane or sheet). The class thresholds 700, 1400 and 2400 pt are the smallest widths holding
two, four and seven 340-pt panes, rounded up; they are prototype defaults in the sense of
specs/12. The rules were then implemented as a pure function and checked by unit tests and the
conformance fixture, so what the specification says is what the core does.

**Unsupported states.** Each matrix row's unsupported state and degradation path was written
against the data model (specs/03, specs/13 ink, specs/21 §6 handoff, the research provider
policy) so that every path names the record that stays portable. None of these rows has an
implementation yet; they are specifications for the tasks that build them.

**Teaching view.** The D18-1 section was carried over unchanged. `grep -n -i "teleprompter\|slide\|sermon\|manuscript" specs/18-platform-capabilities.md`
finds the words only in the section's "Still excluded" line, its external-display line ("not
slide authoring or export"), and "Slide Over" in the display table. No sermon editor,
teleprompter or slide feature is introduced anywhere in the branch.

## The derivation in code

`derive_profile(workspace, class, width_pt, text_size)` returns a `DerivedLayout`: slots,
columns (shown pane, stacked panes of a collapsed group, width, measure flag), tabs, dock
placement and width, the active pane and the effective `LayoutProfile` for the class. The
invariants the tests and the fixture assert on every opening: every pane id appears exactly
once across columns, stacks and tabs; the input workspace is unchanged (so link groups and
scroll anchors are untouched by construction); the active pane is a column's shown pane; the
effective profile passes `check_profile`; `with_profile` changes only the one class entry and
reopens to the same columns and tabs as a stored profile. `check_profile` rejects a profile
that drops a pane, places one twice, names an unknown pane, needs more columns than the class
allows, sizes a pane it does not show, or collapses a group no pane belongs to; the validator
rejects the same shapes in JSON.

## Decisions to review

1. **Class thresholds 700 / 1400 / 2400 pt and column limits 1 / 3 / 6 / 6.** Derived from the
   340-pt minimum, not from readers. A 13-inch iPad in landscape (1366–1376 pt) would hold four
   340-pt panes but is capped at three by the regular class; the Studio Display at default
   scaling (2560 pt) is ultra-wide. B014 may move these.
2. **iPhone landscape stays compact** (one pane plus tabs) although a Pro Max in landscape
   (932–956 pt) would hold two 340-pt panes; the matrix's "1 + tabs" role was kept. The host
   passes the class, so changing this needs no core change.
3. **Widths carry across classes.** When a profile is borrowed from another class and its
   widths cover every shown pane, rule 5 normalises them (seen as 352 / 352 / 320 pt on the iPad with the Greek pane active in a fixture case
   since trimmed; the `crates/workspaces` unit tests still cover the rule). The alternative, equal columns whenever the class
   differs, was not chosen because the Mac's relative widths express intent (a narrower
   lexicon). Reviewers may prefer equal columns.
4. **Two text-size tiers.** `TextSize::Standard` (340 pt) and `TextSize::Accessibility`
   (480 pt) are the two B004 measured; the large non-accessibility Dynamic Type sizes use the
   standard minimum until measured. The accessibility measure cap (900 pt) is the standard cap
   scaled by the same ratio, not a measurement.
5. **The notes dock takes one equal slot**, not the prototype's fixed 360-pt drawer, so that
   1024 pt with the dock open shows two 341-pt panes plus the dock (as the prototype's
   "drawer covers a pane" did) rather than one pane. A single slot stays with the panes and the
   dock becomes a sheet.
6. **Collapsed link groups stack in one column and count once** against the class limit, which
   is why the per-class cap moved from the schema into the validator and the core (878dcae).
   A compact profile may therefore list two visible panes if they share a collapsed group.
7. **`with_profile` writes schema 1.1.** Saving any class on a 1.0 file moves it to 1.1; the
   N reads N-1 rule (ADR 0003) covers readers that still write 1.0.
8. **origin/main was merged into the branch** (2353abf) rather than leaving the conformance
   conflicts to the PR. The merge changed no B006 behaviour; `workspace_layout` was added to
   B006's fixture-kind set.
9. **Shared files touched:** `justfile` and `flake.nix` (wasm check lists gain
   `openlogos-workspaces`), `tools/validate.py`, `crates/conformance/src/lib.rs` and
   `Cargo.toml`, `crates/README.md`, `examples/README.md`, `specs/03-data-model.md` (one
   sentence), `VALIDATION.md`, `Cargo.lock`.
