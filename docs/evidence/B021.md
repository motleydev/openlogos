## Acceptance, item by item

1. **Maintained crypto library selected with compatibility/security review** — met. ADR 0004
   reviews the RustCrypto crates, the dalek crates, `ring`, `age`/`rage`, OpenMLS and `snow` for
   license, maintainers, last release, audit history (the one audit that could be verified from
   a crate's own README is NCC Group's February 2020 review of `chacha20poly1305`; every other
   audit cell says unverified), wasm32 support, pure-Rust status and an estimated size, and
   records the choice and the rejected options. The chosen crates are pinned exactly, compile in
   `just check-wasm`, and live in `crates/sync` only.
2. **Enrollment/revocation/recovery and causal conflict contract specified** — met. ADR 0004
   decisions 3 to 6 and the specs/05 subsection fix: `(issuer, subject)` linked to a locally
   generated vault id by a user-approved link on an active device; vault key per epoch wrapped
   to approved devices and to the recovery identity; approval by an active device or by recovery
   material; revocation with rotation, rewrapping, a cutoff sequence and the documented limit
   that held plaintext and keys cannot be recalled; lost-all-keys recoverable only from the
   recovery code or export; the operation log with content-addressed ids, causal parents,
   per-device sequences, replay and equivocation and unauthorized-operation rejection, sibling
   revisions, observed-remove highlights and tags, final tombstones, acknowledgement-gated
   compaction and the stale-device rule. All of it is executable in `crates/sync` with tests.
3. **No model-designed cryptographic primitives** — met. The ADR's decision 2 and the
   `envelope` module documentation say so explicitly and name the documentation source of each
   construction; the repository contains no cipher, hash, KDF, signature or random-generator
   code; the tests check the libraries against their own published vectors.

## Decisions to review

The ADR lists seven (change kinds and entity ids in the clear; roster as document versus log
operations; recovery code format; Argon2 cost on web and old phones; compaction blocked by silent
devices; rotation only on revocation; hex payload encoding). One more for the lead: `rand_chacha` is a
dev-dependency only, so hosts must bring their own `CryptoRng`; the sync crate depends on no other
workspace crate yet (it will take `core::versioning::SchemaVersion` when a migration exists).
