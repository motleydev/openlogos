## Decisions to review

- **`API_VERSION` 0.1.0 → 0.1.1.** The lib.rs rule says an additive change bumps PATCH while MAJOR is 0; nothing public was removed or changed, so 0.1.1. The Swift and Kotlin host tests assert the literal and were updated; the web test reads the constant from source. Binding surface names are unchanged.
- **`TokenId` keeps its object JSON form** (`{edition, book, chapter, verse, word, suffix}`); fixtures write ids as strings and parse them. Changing the serialized form would be a breaking API change for hosts that already receive records.
- **Tokenization hash is specified, not computed, in the core.** Algorithm fixed in ADR 0003 and specs/19 (SHA-256 over `<id>\t<surface>\n` lines in id order); the core compares hashes and the pipeline computes them, so no hashing dependency enters the wasm build. The fixture and example hashes were computed with that algorithm in Python.
- **Omission is `absent`, not a fifth status.** specs/03 names four statuses; `ReferenceMapping.absent` lists the source verses an explicit absent row covers, and `unknown` those no row mentions. Rows for an omitted verse are stored from `org` into the edition's scheme (`org Mark.16.9 → fixture-shorter-ending: absent`), the one direction that can say "this edition has no text for it".
- **Set status is the worst single status.** English Psalm 13:5 and 13:6 together reach Hebrew 13:6, but the rows are `merge` rows and the record says `partial`, because the rows do not assert that the two together are the whole of 13:6.
- **Lineage deletion orphans before the quote step.** If the lineage says every token under an anchor was deleted, `reanchor_across` returns `Orphaned` without searching the quote, since a hit would be a different occurrence of the same words. A lineage that mentions only some of the tokens falls through to the quote.
- **Pack tables carry no `schema_version`**; the pack manifest versions them and records `core_api_version`. Documents (manifest, collection, receipt, workspace) carry their own.
- **`Fixture::Alignment` is boxed** (clippy `large_enum_variant`); serde is unaffected.
- **Collections item ids** are `^[a-z0-9][a-z0-9-]{3,63}$` so the Obsidian block id is `ol-<item id>` with no escaping; ULID-style upper-case ids would need lower-casing at creation.
- **`additionalProperties: false` stays** in every schema; the newer-MINOR reading rule is carried by serde's default of ignoring unknown fields, and the validator validates each file at its declared version.
- **`specs/sources.json` S06** gains the exact repository path and file hash the alignment fixture was built from, so the fixture's source line resolves to a registered source.
- **Shared files touched outside the B006 scope:** `specs/sources.json` (S06 finding), `justfile` and `flake.nix` (collections added to the wasm check list), `apps/apple/CoreHost/Tests/.../CoreHostTests.swift` and `apps/android/CoreHost/src/test/.../CoreHostTest.kt` (API version literal), `apps/apple/README.md` and `apps/android/README.md` (case count), `crates/ffi/src/native/conformance.rs` (fixture count from `FIXTURE_FILES`), `examples/package-manifest.json` (now 1.1), `VALIDATION.md`, `examples/README.md`, `crates/README.md`, `specs/03-data-model.md`, `specs/19-search-and-retrieval.md`.
