## Rights

The gate passed for S47-macula-greek (37 files), S47-macula-hebrew (941) and S07 (42): status
`approved`, `local_read` and `public_index` allowed, `MANIFEST.sha256` equal to the record and to
`rights/<id>/manifest.sha256`, every listed file's hash; 1,020 files and about 672 MB read and
hashed in 12.5 s.

**The restricted columns never enter a layer, an index or a fixture.** The flags bind: Greek
`ln`, `domain` (UBS MARBLE, Louw-Nida); Hebrew `sdbh`, `lexdomain`, `coredomain`,
`contextualdomain` (UBS SDBH), each "used with permission", not CC BY. Enforced four ways, each
tested: (1) `restricted::check` stops the build unless the excluded list is exactly the set of
backticked names in the record's `restricted_module` flags, every one is in the header and none
is in the allowlist (`the_excluded_columns_are_exactly_what_the_rights_records_flag`,
`a_flag_naming_another_column_or_an_allowlisted_one_stops_the_build`); (2) the TSV reader indexes
only allowlisted columns, so a restricted cell is never read and the row type has no field for one
(`rows_of_one_word_group_and_restricted_cells_are_not_kept`); (3)
`restricted_cells_never_reach_a_layer_or_a_report` builds Greek and Hebrew layers from snippets
of the source's format whose restricted cells hold a marker and finds the marker in no byte of the
layer file or the join report; (4) the second reader checks the built layers: no table has a
column by those names and the manifest lists them under `excluded_columns`. The test fixtures are
hand-written rows in the format with placeholder letters, not corpus data.

Not read at all: S18 MorphGNT, S57 UBS dictionaries, S58 BHSA, S05 STEPBible. Also not carried
from MACULA, though not restricted: `role`, `frame`, `subjref`, `referent`, `participantref`,
`extends` (syntax and referents, B065's), `mandarin`, `stronglemma`, `sensenumber`, `greek` and
`greekstrong` (LXX equivalents), and the lowfat trees. Each layer's attribution says so.

For the steward, not blocking: `rights/S47-macula-hebrew.json` counts 475,910 TSV data rows; the
file has 475,911 (every row parses, has an id and is in the layer; the second reader counts the
same). The record's own count was probably made with `wc -l` on a file without a final newline.

## Decisions

Each is a line of code a reviewer can change; a change is a new layer revision.

1. **A separate overlay.** `just preview-pack-morphology` reads the built text packs and writes
   `~/.cache/openlogos/morphology` (never inside the repository, the corpora or the preview pack,
   which `just preview-pack` replaces whole). A layer's revision names the source commit and the
   text pack revision (`macula-hebrew-47db250-on-oshb-wlc-4.20-3d15126`); its manifest records the
   text pack's `content_revision` and manifest SHA-256. The text packs are not changed.
2. **A layer is a B064 pack** (`schema_version b068-1`, `ol-norm-1`) plus `analysis`, `string`,
   `join_class` and `absence` tables and `layer_*` manifest keys (format `openlogos-morphology-1`).
   The B064 engine attaches it as it is and answers slot queries over it (tested).
3. **A position is a morpheme.** One per Greek word; one or more per Hebrew word, in MACULA's
   segmentation, each with its scalar range inside the pack token. The article a prefix's vowel
   implies (`בָּעוֹף`, 6,435 times; MACULA ids ending in `ה`) is a morpheme with no letters and an
   empty range, not dropped.
4. **Morpheme ids follow `core::identity::mint`**: `wlc:01001001001a`, `…b`; a token of one
   morpheme keeps its id. The upstream `xml:id` is kept beside it. 145,999 WLC tokens hold two
   or more morphemes.
5. **Greek joins by position** (MACULA `ref` `JHN 1:1!5` is `sblgnt:44001001005`), then the
   letters decide the class: `exact`; `punctuation` (the token carries attached punctuation or
   brackets); `elision` (the token's U+02BC, MACULA's `after`); `normalization` (equal once NFC);
   `diacritics` (same letters, another accent or case). Letters that differ beyond that are
   `surface_differs`: not joined, and the token is absent with that reason.
6. **Hebrew joins by walking each verse against the OSHB's own markup**, because MACULA analyses
   the qere and numbers ketiv and qere words alike (Gen 8:17: no `!14`, the qere is `!15`), while
   the pack prints the ketiv. The OSHB main stream must equal the pack's tokens letter for letter or
   the build stops; then each MACULA word must equal what the markup expects next, exactly: the
   written token (`exact`), a qere word (joined to its ketiv token, `qere`), or a qere with nothing
   written (`qere_without_ketiv`). A verse that does not walk would be `unaligned`, listed, nothing
   joined; none occurred. MACULA's own `*`/`**` transliteration marks are not used (Gen 13:3's
   qere has none).
7. **A qere read for a run of ketiv words** (one note for `כי טוב`, Judg 16:25) joins the run's
   first token (`qere_for_ketiv_run`); the others are absent with `ketiv_read_with_previous_token`.
   The markup does not pair words inside a run, so the join does not either.
8. **A ketiv not read** (an empty `rdg`, Ruth 3:12) has no analysis: absent, `ketiv_not_read`.
   **A qere with nothing written** (Ruth 3:5) is in the layer with no token (`token.word` 0) and
   is found by lemma search with its verse; `analyze` cannot reach it, since no token holds it.
9. **Catch words** must repeat the run's letters; a space, a maqqef (1 Sam 9:1) or nothing
   (2 Kgs 6:25) may stand between the words.
10. **Lemma search** is exact when the query is a lemma as the source spells it (points and
    accents included), else by the `ol-norm-1` key of query and lemma (`lemma_key`). Matches are
    grouped by lemma, so homographs that share a key stay apart with their counts (`אמר`: six
    lemmas). A word form is not a lemma (`בְּרֵאשִׁית` finds nothing); Search lemma from a word
    uses the token's last morpheme that is not a suffix.
11. **The parsing in words is composed from MACULA's decoded columns**, not by re-parsing the
    code. Where MACULA leaves a decoded column empty the description does too: a Greek personal
    pronoun's person is only in its code (`P-1DP` reads "pronoun (personal) · dative plural").
12. **Analyses are never merged.** Every installed layer over an edition answers; if two differ in
    lemma or code the token is `conflicting` with both. With one layer per edition today this is
    exercised by tests with two synthetic layers only.
13. **Search lemma (B077).** With no layer installed the row keeps "Needs the lexicon import",
    which the hosts' tests read. With layers, it is enabled on a word of their editions and a word
    of another edition reads "Needs a morphology layer for BSB". The row now carries the word's
    `reference` and `resource_id` (context-menu fixture updated) so the host can find the token;
    the core does not hold the text, so it does not map a scalar offset to a token.
14. **The API is 0.1.6** (additive). `TokenColumns` now uses `Arc` and a `Mutex` instead of `Rc`
    and `RefCell`, so the layers can live behind a host's lock as the edition search does.
15. **Size.** Glosses, renderings, transliterations and a lemma whose bytes are not its NFC key
    are stored once in `string`; the B064 writer's `token_verse` index is dropped from layers
    (the engine reads `token` by position only).
16. **Attribution.** Each layer's attribution is the record's sentence, the licence URI, the source
    and commit, what was changed (the join; the qere joined to ketiv tokens, located by the OSHB
    markup; the restricted columns and the parts not carried) and the CC BY §5 notice. Hosts show it
    with every analysis.

**What MACULA Hebrew carries for ketiv and qere, and whether it can supply the qere.** MACULA
analyses the qere, pointed, and does not carry the ketiv's letters; its word numbers leave a gap
where the ketiv stands. Its 1,278 qere words (1,244 + 25 + 9) are exactly the 1,278 words B071
counted inside the OSHB's qere notes. So the layer supplies the qere the WLC pack omits: for each of
the 1,245 ketiv tokens read as a qere, `analyze` returns `reading: qere` with the qere's letters in
`text` and its analysis; the 9 words read but not written are searchable with their verse. It
cannot supply what is not read (6 ketiv tokens, which correctly have no analysis), and the text pack
is unchanged: a reader still sees the unpointed ketiv until a host shows the analysis's `text`.

rights gate over the NAS; reading, joining and writing take 2.3 s (Greek) and 7.4 s (Hebrew).

|---|---|---|---|

For comparison the WLC text pack is 24.8 MB and its search pack 7.8 MB. The B064 dense columns
(4 bytes per position per feature: 12 features × 475,911 positions for Hebrew) are a third of the
Hebrew layer and are held in memory once attached (about 23 MB Hebrew, 8 MB Greek). A narrower
column encoding would halve them; it is a B064 format change and was not made here.

evenly over the positions and 250 lemmas spread over the frequency ranks (most frequent first),

## B064 fit

- **Fits**: lemma, key, Strong's, code, part of speech, language and every decoded parsing field
  as dictionary columns with roaring postings per value; `Engine::attach_pack` answers
  `TokenQuery` over a layer (`the_b064_engine_answers_slot_queries_over_a_layer`); lemma search
  reads the postings.
- **Does not fit, so in the layer's own tables**: what is shown and not searched (gloss, English,
  transliteration, upstream id, ranges, reading, join class) and the tokens without analysis.
- **Not loaded**: containers. The lowfat trees (clause, phrase, word group) are not imported, so
  `PEER`, `XPEER` and `ANCESTOR` over these layers report the layer unavailable; that is B065's.
  A qere with no written token has `token.word` 0.

## Not verified

- The Mac app's own tests (xcodebuild) and the web shell's Chrome tests were not run; they read
  "Needs the lexicon import", which is unchanged while no layer is installed.
- No host draws an analysis or runs Search lemma yet (the host phase). The scalar-to-token step is
  the host's.
- `conflicting` is exercised only with synthetic layers: MACULA is the only layer per edition.
  The OSHB's own lemma and morphology (S07) could be a second Hebrew layer and give real
  disagreements; not built.
- Memory and attach time on an iPad or an Android device were not measured; the 90 MB of layers
  in a browser is a host-phase concern.
- 830 Greek words have no Berean `gloss` in MACULA (Rev 20:4, 9:20, Mark 16:8, Rom 16:24, …); the
  English rendering is there. Shown as the source has it.
